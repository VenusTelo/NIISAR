1. PROJECT OVERVIEW & PURPOSE
--------------------------------------------------------------------------------
NISAR Monitor is an interactive web application built in Python and Streamlit 
to inspect, compare, and quantify surface changes using L-band Synthetic 
Aperture Radar (SAR) data from the NASA-ISRO NISAR mission.

Why L-Band SAR Matters:
Optical satellites (such as Landsat or Sentinel-2) rely on reflected sunlight 
and cannot see through clouds, smoke, or darkness. In tropical regions like 
Honduras—especially during hurricane season or prolonged wet periods—optical 
imagery is frequently blocked by cloud cover right when ground monitoring is 
most urgent. NISAR operates at L-band microwave frequencies (~24 cm wavelength), 
allowing radar pulses to penetrate clouds and dense vegetation canopies day and 
night.

Origin & Scope:
Developed for the "Dancing with the SARs" challenge at the NASA Space Apps 
Challenge, the application includes pre-configured study sites in Honduras 
(Caratasca Lagoon in Gracias a Dios and Roatán in the Bay Islands) while 
supporting global queries for any coordinate where NISAR acquires data.

Key Design Goal:
Raw NISAR HDF5 (.h5) granules often exceed several gigabytes per scene. Rather 
than requiring users or evaluators to download entire granules locally before 
viewing results, NISAR Monitor streams spatial subsets directly from NASA's 
cloud archive over HTTPS and converts complex radar arrays into both 
plain-language visual summaries and quantitative scientific metrics.


2. INSTALLATION & RUNNING THE APPLICATION
--------------------------------------------------------------------------------
The application runs locally on Windows, macOS, or Linux using Python 3.9 or 
newer. Everything is contained inside a single Python script (`app.py`) with 
no external C/C++ GIS binaries (like GDAL) required.

Step 1: Open a Terminal in the Project Folder
Navigate to the directory containing `app.py` (for example, in Windows 
PowerShell or macOS/Linux Terminal):

   cd path/to/nisar-monitor

Step 2: Create and Activate a Virtual Environment
Creating an isolated environment keeps dependencies clean:

   python -m venv .venv

   # On Windows (PowerShell):
   .\.venv\Scripts\Activate.ps1

   # On macOS / Linux:
   source .venv/bin/activate

(Note for Windows users: If PowerShell blocks script activation, you can run 
the interpreter directly without activating by prefixing commands with 
`.\.venv\Scripts\python.exe -m ...`).

Step 3: Install Required Python Libraries

   pip install streamlit asf_search earthaccess h5py numpy pandas pydeck altair

Step 4: Launch the Application

   streamlit run app.py

   # Or on Windows without activating .venv:
   .\.venv\Scripts\python.exe -m streamlit run app.py

Step 5: Open in Browser
Streamlit will print a local URL in the terminal:
   Local URL: http://localhost:8501

Your default web browser should open this address automatically. To stop the 
application at any time, return to the terminal window and press Ctrl + C.


3. SYSTEM ARCHITECTURE & UNDER-THE-HOOD DESIGN
--------------------------------------------------------------------------------
For technical evaluators reviewing how the software works internally, the 
pipeline is organized into five main stages inside `app.py`:

A) Catalog Discovery (`asf_search`)
   When coordinates and a product level are selected, `buscar_escenas_punto()` 
   queries the Alaska Satellite Facility (ASF) API using a WKT `POINT(lon lat)` 
   filter, processing level, relative orbit (Track), and Frame. If a strict 
   Track/Frame search returns zero granules, the function automatically falls 
   back to an unconstrained orbit search over that coordinate. Results are 
   cached for 1 hour via `@st.cache_data(ttl=3600)`.

B) Remote HDF5 Cloud Streaming (`earthaccess` + `h5py`)
   Instead of calling `earthaccess.download()`, the reader opens a remote 
   file-like object via `earthaccess.open([url_h5])` and passes it straight to 
   `h5py.File(..., "r")`. It traverses `/science/LSAR/{PRODUCT}` to locate 
   coordinate vectors (`xCoordinates`, `yCoordinates`), pixel spacing attributes, 
   and projection EPSG codes before reading any 2D raster blocks.

C) Adaptive Frequency & Stride Selection
   - On `GCOV` products, when the user selects a regional window ($\ge 60\text{ km}$), 
     the reader automatically switches from `frequencyA` to `frequencyB` to 
     keep cloud transfer fast. For local windows ($< 60\text{ km}$), it reads 
     `frequencyA` for finer spatial detail.
   - If a requested bounding window exceeds $1600 \times 1600$ pixels, a 
     dynamic decimation `stride` is applied so the browser renders smoothly 
     without exhausting RAM.
   - Complex datasets (`GSLC`/`RSLC`) stored either as NumPy complex numbers or 
     compound `('r', 'i')` structs are converted to magnitude via 
     $\sqrt{r^2 + i^2}$.

D) Pure-Python Geodetic Projection Engine
   To avoid heavy GDAL/PROJ installation failures across operating systems, 
   `latlon_a_proyeccion()` and `proyeccion_a_latlon()` implement analytical 
   forward and inverse map projections directly in Python/NumPy for:
   - Geographic WGS84 ($EPSG:4326$)
   - Universal Transverse Mercator North and South ($EPSG:32601$–$32660$ and 
     $EPSG:32701$–$32760$)
   - EASE-Grid 2.0 Global Cylindrical Equal-Area ($EPSG:6933$), used by NISAR 
     Level 3 Soil Moisture (`SME2`) products.

E) Multi-Date Spatial Alignment (`alinear_mallas`)
   When comparing Date 1 and Date 2, the two granules may have slightly shifted 
   bounding grids or different pixel spacings. `alinear_mallas()` computes the 
   exact overlapping bounding box in projected coordinates and uses binary 
   search (`np.searchsorted`) via `indices_mas_cercanos()` to resample Date 2 
   onto Date 1's exact pixel grid before computing any difference metrics.


4. SIGNING IN WITH NASA EARTHDATA
--------------------------------------------------------------------------------
All NISAR data distributed through ASF is free, but NASA requires an active 
Earthdata Login session to stream files.

1. In the left sidebar under "1. NASA Earthdata Account", enter your 
   Earthdata Username and Earthdata Password.
2. Important: Enter your USERNAME (e.g., `jdoe_nasa`), not your email address. 
   NASA's URS authentication endpoint rejects email addresses during programmatic 
   login.
3. If you need a free account, register at:
   https://urs.earthdata.nasa.gov/


5. DUAL DISPLAY MODES (INTUITIVE VS. SCIENTIFIC)
--------------------------------------------------------------------------------
Right below the login inputs in the sidebar, the "Display Mode" radio button 
switches the interface between two audiences without reloading the satellite 
data:

1) Intuitive (for the general public)
   Built for emergency managers, farmers, local authorities, and students who 
   need clear takeaways without radar jargon:
   - Displays clean side-by-side imagery for Date 1, Date 2, and Difference.
   - Presents a simplified physical summary table.
   - Places a blue `(i)` info badge on every row of the results table. Hovering 
     over `(i)` displays a plain-language tooltip explaining what that metric 
     means on the ground.

2) Scientific (for the technical community)
   Built for NASA evaluators, remote sensing researchers, and GIS analysts:
   - Displays a calibrated Color Scale legend panel next to the imagery with 
     exact physical thresholds and units ($dB$, $rad$, or $m^3/m^3$).
   - Renders a "Data Interpretation" reference table mapping value intervals 
     to surface scattering mechanisms or soil states.
   - Computes statistical dispersion metrics: Date 1 Mean, Date 2 Mean, Net 
     Change, Date 1 & Date 2 Standard Deviations ($\sigma$), and the Coefficient 
     of Variation ($CV = \frac{\sigma_{\Delta}}{|\mu_{\Delta}|}$).
   - Opens an interactive "HDF5 (.h5) File Contents" inspector next to the map 
     with two tabs:
       * `Variables (.h5)`: Lists internal HDF5 dataset paths, array dimensions, 
         and data types.
       * `Metadata`: Displays raw `/science/LSAR/identification` attributes 
         (such as `zeroDopplerStartTime`, mission cycle, and polarization).


6. CONFIGURING STUDY AREA, SCALE & ORBITAL PARAMETERS
--------------------------------------------------------------------------------
Under "2. Study Area & Analysis Scale" in the sidebar:

- Study Area Presets:
  * `Gracias a Dios / Caratasca Lagoon (Track 4, Frame 9)`: Coastal lagoon and 
    wetland system in eastern Honduras ($15.1500^\circ\text{ N}, -83.9000^\circ\text{ W}$).
  * `Roatán / Bay Islands (Track 105, Frame 10)`: Caribbean island coastline 
    and reef/urban interface ($16.3200^\circ\text{ N}, -86.5300^\circ\text{ W}$).
- Custom Coordinates:
  Enter any Latitude ($+N / -S$) and Longitude ($+E / -W$) in decimal degrees.
- Measurement Area Slider ($2\text{ km}$ to $250\text{ km}$):
  * $2\text{ km}$ – $58\text{ km}$: Local high-detail zoom around the target pin.
  * $60\text{ km}$ – $248\text{ km}$: Regional watershed or coastal view.
  * $250\text{ km}$: Switches to "Full map" mode, reading the entire scene 
    footprint.
- Track & Frame:
  Leave the preset numbers for repeat-pass geometry, or set `Track = 0` and 
  `Frame = 0` (`0 = any`) when testing custom global coordinates to retrieve 
  all available passes.


7. SUPPORTED NISAR PRODUCTS & PHYSICAL FORMULAS
--------------------------------------------------------------------------------
Select any of the five NISAR product levels in the "NISAR map type" dropdown:

1) GCOV — Level 2 (Geocoded Polarimetric Covariance)
   - Primary variable: Co-polarized backscatter (`HHHH` or `VVVV`) and 
     cross-polarized backscatter (`HVHV` or `VHVH`), converted from linear power 
     $\sigma^0$ to decibels via:
     $$\sigma^0_{dB} = 10 \log_{10}(\sigma^0)$$
   - Physical interpretation:
     * $< -20\text{ dB}$: Calm open water / specular reflection.
     * $-20$ to $-17\text{ dB}$: Open water / very wet bare soil.
     * $-17$ to $-12\text{ dB}$: Low or agricultural vegetation / wetlands.
     * $-12$ to $-7\text{ dB}$: Dense forest canopy (volume scattering).
     * $> -7\text{ dB}$: Urban structures or very rough terrain.
   - Calculated Metrics:
     * Open water / inundation area ($km^2$, pixels with $\sigma^0_{co} < -17\text{ dB}$).
     * Dense forest cover ($km^2$, pixels with $\sigma^0_{cr} > -16\text{ dB}$) and 
       net forest change in hectares ($ha$).
     * Low / agricultural vegetation area ($km^2$, $-21\text{ dB} \le \sigma^0_{cr} \le -16\text{ dB}$).
     * Radar Vegetation Index ($RVI$):
       $$RVI = \frac{4 \sigma^0_{cr}}{\sigma^0_{co} + \sigma^0_{cr}}$$

2) GUNW — Level 2 (Geocoded Unwrapped Interferogram)
   - Primary variable: Unwrapped interferometric phase $\Delta \phi$ in radians 
     ($rad$), plus `coherenceMagnitude` ($0$ to $1$).
   - Physical conversion: Phase is converted to Line-of-Sight (LOS) surface 
     displacement in centimeters using the L-band wavelength ($\lambda \approx 24\text{ cm}$):
     $$\Delta d_{cm} = \Delta \phi \cdot \left(\frac{-24.0}{4\pi}\right)$$
   - Calculated Metrics:
     * Mean interferometric phase ($rad$) and LOS displacement ($cm$).
     * Annualized deformation velocity ($mm/yr$) scaled by elapsed days.
     * Deformed area exceeding $2\text{ cm}$ ($km^2$).
     * Spatial deformation gradient ($mm/km$) computed via 2D finite differences 
       (`np.gradient`).
     * Mean temporal coherence ($0$ to $1$).

3) SME2 — Level 3 (Soil Moisture)
   - Primary variable: Volumetric soil moisture ($\theta_v$) in $m^3/m^3$ 
     (preferring the `DSG` algorithm candidate when present) and cross-polarized 
     HV backscatter (`sigma0HV`) in $dB$.
   - Physical interpretation:
     * $0.00 - 0.15\ m^3/m^3$: Very dry soil.
     * $0.15 - 0.30\ m^3/m^3$: Dry soil / sparse vegetation.
     * $0.30 - 0.45\ m^3/m^3$: Moderate to high soil moisture.
     * $> 0.40\ m^3/m^3$: Saturated soil (high runoff / flood risk).
   - Calculated Metrics:
     * Mean volumetric moisture ($m^3/m^3$) and percentage moisture ($\%$).
     * Saturated area $> 0.40\ m^3/m^3$ within the common overlap ($km^2$).
     * Saturated area $> 0.40\ m^3/m^3$ across the full uncropped scene ($km^2$).
     * Spatial Pearson correlation ($r$) between Date 1 and Date 2 moisture maps.

4) GSLC — Level 2 & 5) RSLC — Level 1 (Single Look Complex)
   - Primary variable: High-resolution complex radar amplitude converted to 
     decibels via:
     $$A_{dB} = 20 \log_{10}(|Z|)$$
   - Difference: `GSLC` is geocoded onto map coordinates (`grids`), whereas 
     `RSLC` remains in native radar slant-range/azimuth geometry (`swaths`).
   - Performance note: Because SLC files contain full-resolution complex 
     samples without multi-looking, streaming takes longer. Keep the 
     Measurement Area slider under $20\text{ km}$ when inspecting SLC granules.


8. INTERPRETING MAPS, TABLES & CHARTS
--------------------------------------------------------------------------------
Once two dates ("Date 1 (Before)" and "Date 2 (After)") are selected at the 
top of the main page:

- Geometry Consistency Check:
  Because SAR is side-looking, comparing an `Ascending` pass with a `Descending` 
  pass introduces radar layover/shadow differences. If Date 1 and Date 2 have 
  different Tracks or flight directions, the app displays a warning banner and 
  restricts all calculations to their valid overlapping pixels.

- Visual Panels:
  * Date 1 (Before) & Date 2 (After): Individual renders of the selected window.
  * Difference (Common Area): Diverging Blue–White–Red map where BLUE indicates 
    a decrease ($\Delta < 0$, e.g., drying soil or receding water) and RED 
    indicates an increase ($\Delta > 0$, e.g., wetter soil or flood expansion).

- Interactive Map Location (PyDeck):
  * Light/Dark Blue Polygons: Full footprints of Date 1 and Date 2 granules.
  * Red Bounding Box: Exact cropped area under analysis.
  * Georeferenced Raster Overlay: Projected difference cells draped over the 
    Carto Voyager basemap so changes can be tied to rivers, roads, and towns.
  * Yellow Pin: Target coordinate.

- Results Section ("Table" and "Charts" Tabs):
  * Table Tab: Side-by-side comparison of exact elapsed time (days and UTC 
    timestamps), common analyzed area ($px$ and $km^2$), and all derived 
    physical metrics.
  * Charts Tab: Altair two-point trajectory charts for each metric plus a 
    "Common Pixel Distribution" probability density curve comparing Date 1 
    (blue) against Date 2 (orange/red).


9. EXAMPLE EVALUATION WORKFLOWS
--------------------------------------------------------------------------------
Workflow 1: Coastal Wetland & Flood Monitoring (GCOV)
1. Select `Gracias a Dios / Caratasca Lagoon (Track 4, Frame 9)`.
2. Choose `GCOV — Level 2` and set Measurement Area to `62 km`.
3. Select two different acquisition dates on Track 4.
4. Switch between `Intuitive` and `Scientific` modes to inspect how the app 
   translates backscatter ($dB$) into open water ($km^2$), forest cover ($ha$), 
   and $RVI$ for different audiences.

Workflow 2: Soil Moisture & Saturation Tracking (SME2)
1. Switch NISAR map type to `SME2 — Level 3`.
2. Pick two dates over the study area.
3. Inspect the `Table` and `Charts` tabs to compare volumetric soil moisture 
   ($m^3/m^3$), saturation extent ($> 0.40\ m^3/m^3$), and spatial correlation ($r$).

Workflow 3: Global Arbitrary Coordinate Test
1. Set `Track = 0` and `Frame = 0` in the sidebar.
2. Enter any Latitude/Longitude worldwide where NISAR data exists.
3. Pick two scenes from the populated dropdowns and inspect the HDF5 internal 
   tree in `Scientific` mode.


10. TROUBLESHOOTING
--------------------------------------------------------------------------------
- "No scenes found. Try setting Track = 0 and Frame = 0."
  The active Track/Frame filter does not intersect your coordinates. Set both 
  to `0` to search across all orbital passes.

- "Coordinates are outside the scene's data coverage."
  The outer metadata bounding box includes your coordinate, but the valid 
  radar swath pixels inside the `.h5` grid do not reach that exact point. 
  Move your Latitude/Longitude slightly toward the center of the blue polygon 
  shown on the map.

- "No valid overlapping pixels found within this area."
  The two chosen dates do not share valid pixels inside your small zoom box. 
  Increase the Measurement Area slider or select two dates from the same Track.

- Slow loading on GSLC or RSLC:
  Reduce the Measurement Area slider to `10 km`–`20 km` so `h5py` streams only 
  a small slice of the high-resolution complex array.
